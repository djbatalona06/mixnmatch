mix n match layout board

The plan for every screen. Think of each screen as 12 equal strips side by side. Every box says how many strips it uses, at phone, tablet and desktop width. The real app is measured against the rules by npm run layout:check, which writes the measured report with screenshots.

16px side gutter one of the 12 columns a part of the screen Showing: phone (375px)

The rules every screen follows

Each rule is measured on the real app at all three widths. The check fails if any screen breaks one.

RuleThe numberWhere it is setHow it is measured
Side gutter 16px on each side px-4 on the header row and on <main> (app/src/components/chrome.tsx) On a phone, the content starts exactly 16px from the left edge. (side-gutter)
Content width at most 72rem (1152px) max-w-6xl mx-auto on the header row, <main> and the footer The content area is never wider than 1152px. (max-width)
Header lines up same left edge The header row and <main> use the same width and gutter The header's left edge matches the content's left edge, at every width. (header-lines-up)
Easy to tap at least 44px tall on a phone min-h-[44px]; small buttons are 44px on phones and 40px from 768px up (app/src/components/ui.tsx) Every link, button, field, tab and checkbox label on a phone. Links inside a sentence are allowed to be smaller. (tap-size)
Clear of the bottom tabs tabs are 60px + a 1px line; the page keeps 112px free below pb-28 on <main>; floating bars sit 61px up (bottom-[calc(61px+…)]) On a phone, the end of the page and any floating bar stay above the tabs. (tab-bar-clearance)
No sideways scrolling page width = window width Long names use truncate or break-all; wide rows wrap The page is never wider than the window. (no-sideways-scroll)
